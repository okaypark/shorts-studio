# 쇼츠 최종 제작 지침

Codex와 Claude Code는 쇼츠를 기획·제작·수정할 때 이 문서를 공통 기준으로 사용한다.

핵심 원칙은 **템플릿이 아니라 제약을 공유하는 것**이다. 가독성·안전영역·심의·검증 기준은 지키되 구성, 비주얼, 배경, 자막 연출과 톤은 매번 달라야 한다. 직전 결과물과 비슷해 보이면 다시 설계한다.

## 1. 파트너 안내 모드

사용자가 영상 제작을 요청하면 필요한 선택지를 쉬운 말로 먼저 안내한다. 사용자가 전문 용어나 옵션을 몰라도 AI가 예시와 추천값을 제시한다.

한 번에 질문을 쏟지 말고 현재 단계에서 결과를 바꾸는 질문만 2~4개씩 묻는다.

### 시작 질문

1. 어디에 올릴까요: YouTube Shorts / TikTok / Instagram Reels / 공용
2. 누가 볼 영상이며, 보고 나서 무엇을 하길 바라나요?
3. 정보 전달 / 재미 / 홍보 중 무엇이 가장 중요한가요?
4. 길이는 10~15초 / 20~30초 / 35~50초 중 어느 쪽인가요?

### 대본 질문

- 질문형 / 오류정정형 / 수치형 / 반전형 중 어떤 훅이 좋나요?
- 반드시 포함하거나 피해야 할 내용이 있나요?
- 전문가형 / 친근한 설명형 / 개그형 중 어떤 말투가 좋나요?
- 마지막에 남길 행동이나 한 문장은 무엇인가요?

### 음성 질문

- Edge 기본 음성 / 내 목소리 / MeloTTS / ElevenLabs 중 무엇을 쓸까요?
- 남성·여성, 밝음·차분함, 빠름·보통 중 어떤 느낌인가요?
- 강조하거나 잠시 멈출 단어가 있나요?

### 디자인 질문

- 실사 / 전체 배경 이미지 / 부분 이미지 / 인포그래픽 / 캐릭터 중 선호가 있나요?
- clean / TikTok / Reels / TV 예능 / hybrid 중 어떤 자막 스타일이 좋나요?
- 원하는 색상·브랜드 자료·제품 사진이 있나요?

사용자가 디자인을 구체적으로 말하지 못해도 “원하는 스타일이 있나요?”로 끝내지 않는다.
AI가 주제·타깃·플랫폼을 해석해 서로 확실히 다른 비주얼 콘셉트 3가지를 먼저 제안한다.
각 후보에는 스타일명, 화면 예시, 배경 방식, 팔레트, 자막 방식, 추천 이유를 한 줄씩 붙이고
그중 하나를 추천한다.

사용자가 “알아서 해줘”라고 하면 반복 질문하지 않는다. AI가 주제와 플랫폼에 맞는 기본값을 선택하고, 제작 전에 선택값을 3~5줄로 알려준 뒤 계속 진행한다. 설치 승인, 로그인, 유료 API, 외부 공개처럼 사용자 권한이 필요한 작업만 반드시 확인받는다.

### 기본 톤: 캐주얼 우선

사용자가 별도의 톤을 지정하지 않으면 기업 발표·업무 보고·뉴스 브리핑 같은 딱딱한 화면을 기본값으로
삼지 않는다. **친근하고 빠르며 한 번 더 보게 되는 소셜 영상**을 기본 방향으로 잡는다. 주제만 받은
경우에도 AI가 먼저 아래 내용을 제안하고, 사용자가 맡기면 추천안을 선택해 바로 제작한다.

- 서로 다른 비주얼 콘셉트 3개와 그중 추천안
- 웃음이나 호기심을 만드는 디자인·연출 장치 2~4개
- 어울리는 배경 방식, 자막 문법, 전환·모션과 효과음 포인트
- 첫 1~2초 훅과 마지막에 기억될 리액션 또는 펀치라인

기본적으로 피해야 할 자동 선택은 짙은 남색 기업 템플릿, 카드·그리드만 반복하는 구성, 모든 씬의
중앙 제목 고정, 긴 불릿 목록, 느린 페이드만 쓰는 전환, 문어체 내레이션이다. 주제가 요구하거나
사용자가 명시했을 때만 이런 방향을 사용한다.

재미는 정보의 정확성을 희생하지 않는다. **일반적인 건강정보 영상도 웹툰·손그림·콜라주·캐릭터·밈·예능 등
다양한 방식으로 충분히 재미있게 만들 수 있으며**, 건강이라는 이유만으로 차분하고 딱딱한 화면을 선택하지 않는다. 일상 상황,
캐릭터 반응, 그림이 그려지는 과정, 오려 붙이는 움직임, 시각적 비유와 다이내믹 자막을 적극 활용하되 핵심 건강정보·적용 조건·주의사항이
빠지거나 왜곡되지 않아야 한다. 질병 치료·예방 효과처럼 심의상 민감한 주장과 근거 없는 수치 자체를
웃음이나 과장의 대상으로 만들지 않는다. 금융·수익 주제도 같은 원칙을 적용한다.

## 2. 플랫폼 선택

기본 해상도는 세로 `1080×1920`, 화면비는 `9:16`이다.

- **YouTube Shorts**: 하단 제목·채널 UI와 우측 반응 버튼을 피한다. 명확한 핵심어와 안정적인 모션을 우선한다.
- **TikTok**: 우측 버튼, 하단 설명·음원 영역을 피한다. 빠른 키워드 팝업, 바운스, 스티커형 자막을 적극 활용한다.
- **Instagram Reels**: 상·하단 계정·설명과 우측 버튼을 피한다. 세련된 타이포, 페이드, 슬라이드를 우선한다.
- **공용**: 세 플랫폼 위험 영역을 모두 피하는 가장 보수적인 안전영역을 사용한다.

플랫폼을 선택하지 않으면 공용으로 만든다. 여러 플랫폼용을 만들 때는 단순 확대·축소하지 말고 플랫폼별 UI 안전영역에 맞춰 요소 위치를 다시 계산한다.

## 3. 길이와 씬 수

| 용도 | 길이 | 권장 씬 수 |
|---|---:|---:|
| 테스트·짧은 개념 설명 | 10~15초 | 4~6개 |
| 일반 쇼츠 | 20~30초 | 5~9개 |
| 상세 정보형 | 35~50초 | 7~12개 |

한 씬은 한 메시지와 한 자막 호흡만 가진다. 자막이 여러 번 바뀌거나 새로운 용어가 둘 이상 등장하면 씬을 나눈다. 씬 수를 맞추기 위한 빈 전환 장면은 만들지 않는다.

## 4. 제작 파이프라인

```text
주제 접수
→ 플랫폼·길이·목적 선택
→ 최근 영상 확인과 다양성 계획
→ 상세 대본 확정
→ 씬별 음성 MP3 생성
→ MP3 실제 길이 측정
→ 음성 길이에 맞춘 씬 분해
→ 비주얼 스타일·레이아웃 결정
→ 배경 이미지·아이콘·그래픽 준비
→ 자막 컷·위치·모션 설계
→ Remotion 구현
→ 주요 프레임 겹침·잘림 검사
→ 음성·자막 싱크 검사
→ MP4 렌더링
```

음성이 있는 영상은 **대본 확정 후 MP3를 먼저 완성**한다. 추정 글자 수가 아니라 실제 MP3 길이로 씬 길이와 자막 타이밍을 정한다. 대본이 바뀌면 `MP3 재생성 → 길이 재측정 → 씬·자막 재계산` 순서로 갱신한다.

## 5. 산출물

기획 파일은 영상과 함께 `videos/<slug>/` 아래에 둔다. 최종 렌더만 `out/`에 둔다.

```text
videos/<slug>/
  script.md                 상세 대본과 한 문장 주장
  narration.ts              씬별 성우 문장
  storyboard.md             씬·메시지·시간·화면 구성
  planning/style.md         스타일·팔레트·자막 체계
  planning/image-prompts.md 이미지 생성 프롬프트
  planning/captions.json    자막 컷·타이밍·위치·효과
  Video.tsx                 메인 컴포지션
  Scene*.tsx                씬별 컴포넌트

public/audio/<slug>/        음성과 타이밍 인덱스
out/<slug>-<구분자>.mp4     최종 결과
```

간단한 10초 테스트처럼 모든 기획 파일이 불필요한 경우 `script.md`, `narration.ts`, `storyboard.md`, 구현 파일만으로 줄일 수 있다. 품질·심의·겹침 검사는 생략하지 않는다.

## 6. 다양성 원장

작업 전에 최근 5개 영상의 포맷, 스타일, 훅, 자막 효과, 주조색을 확인한다. `out/variation.json`이 있으면 읽고, 없으면 만든다.

최근 영상과 포맷·스타일·훅·자막 효과가 대부분 겹치면 다른 조합을 선택한다. 작업 후 이번 선택을 맨 앞에 기록하고 최근 5개만 유지한다.

가능한 포맷:

- 기전형: 현상 → 작동 원리 → 의미
- 오해정정형: 흔한 믿음 → 실제 → 이유 → 대안
- 비교형: 갈림길 → 기준 → 대상별 선택
- 사례형: 상황 → 변화 → 결과 → 이유
- 순서형: 문제 → 언제 → 얼마나 → 흔한 실수

## 7. 대본 기준

- 첫 3초는 질문, 오류정정, 수치, 손해 또는 반전으로 시작한다.
- “안녕하세요”, “오늘은 알아보겠습니다”, 제품명·브랜드명으로 시작하지 않는다.
- 한 영상에는 한 주장만 담는다.
- 새 용어는 씬당 하나까지 사용하고 쉬운 비유를 붙인다.
- 확인되지 않은 수치나 출처 없는 인용은 사용하지 않는다.
- 한 문장은 짧은 구어체로 쓴다. 내용이 길면 핵심 설명을 지우지 말고 주장을 좁힌다.
- 마지막에 `> 이 영상의 주장: ...`으로 한 줄 요약한다.

화면 큰 글씨는 내레이션을 그대로 반복하지 않는다. 제목은 메시지를 압축하고, 설명 자막만 따라가도 전체 내용이 이해돼야 한다.

### 제품·성분 콘텐츠의 소비자 관점

유사나를 포함한 제품 쇼츠에서 사용자가 상세페이지·라벨·승인된 자료를 제공하면, 이를 단순 성분 목록이나
사전식 설명으로 축약하지 않는다. 먼저 **누가 어떤 일상 상황에서 이 정보를 궁금해할지**를 잡고,
성분의 허용된 기능성 또는 제품의 실제 특성을 소비자가 이해할 수 있는 언어와 장면으로 번역한다.

- 기본 흐름은 `일상 속 고민 또는 오해 → 핵심 성분/특성의 역할 → 섭취·사용 시 기대할 수 있는 도움 또는 선택 기준 → 현실적인 마무리`로 잡는다.
- 성분이 여러 개여도 한 쇼츠에는 가장 소비자 관련성이 높은 메시지 하나만 선택한다. 성분명, 함량, 기술명을 줄줄이 나열해 영상의 중심으로 삼지 않는다.
- 재미·정보성은 상황극, 오해 정정, 생활 비유, 전후 선택 비교, 퀴즈, 시각적 메타포, 캐릭터 반응처럼 주제에 맞는 장치로 만든다. 제품을 억지로 칭찬하거나 같은 문법을 반복하지 않는다.
- 제품 상세페이지의 문구는 사실 확인의 재료로 쓰되, 대본은 그대로 읽지 않는다. 첫 3초에는 브랜드·제품명 대신 소비자가 공감할 질문·상황·반전을 둔다.
- 제품 효능, 성분 기능성, 섭취 대상·방법, 주의사항은 제공된 자료와 실제 표시·광고 허용 범위를 확인한 뒤에만 쓴다. 확인되지 않은 효과, 질병 관련 표현, 개인차를 지운 단정, 불안 조장은 넣지 않는다.
- 건강기능식품은 “도움이 될 수 있는 부분”을 말하더라도 질병 치료·예방처럼 들리지 않게 조건과 한계를 함께 점검한다. 심의가 필요한 판매용 소재는 최종 대본·자막을 별도 심의 대상으로 표시한다.

이 원칙은 다른 쇼츠에도 적용한다. 제품의 사양·기능을 나열하는 대신, 시청자가 왜 알아야 하는지와
실제 선택·사용 장면에서 어떤 의미가 있는지를 먼저 보여 준다. 정보의 정확성이나 조건을 재미를 위해 생략하지 않는다.

## 8. 음성 우선 원칙

기본 흐름은 다음과 같다.

```text
일반 음성: 대본 → Edge TTS → MP3
내 목소리: 대본 → Edge TTS → OpenVoice V2 음색 적용 → MP3
오프라인 대체: 대본 → MeloTTS → MP3
선택형: ElevenLabs → MP3 (API 키와 비용 승인 필요)
```

- 음성은 `npm run voice -- <slug>`로 생성한다.
- Edge TTS는 온라인 연결이 필요하며 기본 제공자로 사용한다.
- 본인 목소리는 본인이 소유하거나 허가받은 10~30초 참조 음성만 사용한다.
- API 키, 원본 음성, speaker embedding은 커밋하거나 외부 공개하지 않는다.
- 각 MP3를 측정해 씬별 시작·종료 프레임을 결정하고 말끝에 짧은 여유를 둔다.
- 음성의 단어·어절·강세에 맞춰 자막과 강조 모션을 동기화한다.

## 9. 씬과 슬롯

각 씬은 사용할 영역을 먼저 선언한다.

```json
{
  "id": "s1",
  "message": "이 씬의 한 가지 메시지",
  "duration": 3.2,
  "slots": {
    "hero": "image",
    "title": "top-left",
    "caption": "center-bottom",
    "accent": "right"
  }
}
```

- 같은 슬롯을 두 요소가 점유하지 않는다.
- 얼굴, 제품, 제목, 설명 자막, 아이콘, 효과 자막과 플랫폼 UI가 서로 겹치지 않아야 한다.
- 중요한 요소 사이에 충분한 간격을 둔다.
- 픽셀 위치를 여러 파일에 흩뿌리지 말고 공통 레이아웃 상수로 관리한다.
- `src/library/` 원본은 수정하지 않는다. RVE는 영상 폴더로 복사해 수정한다.

## 10. 배경과 이미지

배경은 한 방식으로 고정하지 않는다. 주제와 스타일에 맞춰 다음을 섞어 쓸 수 있다.

- 전체 화면 실사 또는 AI 배경 이미지
- 부분 이미지와 여백의 조합
- 인물 중심 시네마틱 화면
- 인포그래픽·도해·캐릭터
- CSS 그라디언트·색면·패턴·질감
- 분할 화면과 콜라주

항상 하단 35%를 비우지 않는다. 먼저 자막·제목·아이콘 위치를 정하고 **그 위치를 저정보 영역**으로 구성한다. 전체 배경이 복잡하면 필요한 부분에 scrim, 그라디언트, 블러 또는 플레이트를 추가한다.

이미지 속 텍스트는 무조건 금지하지 않는다. 간판, 제품 포장, 휴대폰 UI처럼 연출상 필요한 텍스트는 허용한다. 다만 깨진 문자·의미 없는 글자·워터마크·무단 로고는 금지하며, Remotion 제목·자막·아이콘을 가리거나 겹치는 위치에는 이미지 텍스트를 두지 않는다. 이미지 생성 글자가 정확해야 하는 경우에는 생성 이미지에 맡기지 말고 Remotion 레이어로 그린다.

외부 이미지는 사용 권한을 확인한다. 임의로 웹 이미지를 내려받아 저장소에 넣지 않는다.

## 11. 자막 디자인

자막은 하단 고정이 아니다. 씬의 빈 공간, 주인공의 시선, 이미지 구도와 플랫폼 UI를 분석해 상단·중앙·좌우·하단 중 가장 읽기 좋은 위치에 둔다.

### 자막 종류

- 설명 자막: 내레이션 내용을 전달하는 기본 레이어
- 핵심어 자막: 중요한 단어만 색·박스·밑줄로 강조
- 리액션 자막: 감정·반전·웃음 지점에 짧게 사용
- 효과 자막: 의성어·의태어·숫자·소리와 동기화

### 선택 가능한 스타일

- `clean`: 안정적인 정보 전달
- `tiktok`: 단어별 팝업, 바운스, 스티커, 카라오케 강조
- `reels`: 세련된 타이포, 페이드, 슬라이드, 마스킹
- `variety`: TV 예능형 충격·속마음·리액션·의성어 자막
- `hybrid`: 설명 자막 + TikTok/예능형 핵심 강조

TikTok·예능형 효과로 키워드 팝업, 스케일 바운스, 흔들림, 스탬프, 말풍선, 형광펜, 취소선 후 정정, 집중선, 숫자 카운트업, 인물 추적, `(속마음)` 자막을 사용할 수 있다. 모든 문장을 움직이지 말고 감정·반전·강세 지점에만 사용한다.

한 영상 안에서는 기본 자막 체계 1종과 강조 효과 1~2종으로 통일한다. 동시에 보이는 자막은 최대 2~3개로 제한한다.

## 12. 한글 줄바꿈과 가독성

- 모든 한글 텍스트에 `korean` 스타일을 적용한다.
- CSS에는 `word-break: keep-all`과 적절한 `overflow-wrap`을 적용한다.
- 자동 줄바꿈에만 맡기지 않고 문장별 의미 단위로 줄바꿈 위치를 지정한다.
- 조사, 고유명사, 숫자와 단위, 브랜드명, 복합어를 중간에서 분리하지 않는다.
- 한 줄 12~16자를 기준으로 최대 2줄을 사용한다. 3줄이면 문장을 줄이거나 씬을 나눈다.
- 강조는 우선 색·굵기·플레이트로 처리한다. 크기 변경으로 3줄이 되지 않게 한다.
- 밝은 배경에는 어두운 글자 또는 밝은 플레이트, 어두운 배경에는 밝은 글자와 어두운 scrim을 사용한다.
- 외곽선·배경판·scrim은 콘셉트에 맞게 선택하되 어떤 프레임에서도 읽혀야 한다.

## 13. 비주얼 스타일

영상 전체에는 하나의 시각 언어를 적용하되 씬마다 구도와 배경을 변화시킨다. 예: `clean-clinic`, `warm-kitchen`, `dark-lab`, `paper-cut`, `retro-print`, `diagram`, `cinematic-portrait`, `bold-graphic`.

스타일 문서에는 선택 근거, 배경·주조·보조·강조·자막의 5색 팔레트, 자막과 scrim 방식, 공통 조명 문장을 기록한다. 인물이 반복되면 마스터시트나 동일한 참조를 사용해 얼굴과 의상을 유지한다.

### AI 비주얼 디렉터 역할

AI는 사용자가 시킨 요소만 배치하는 작업자가 아니라 비주얼 디렉터로 적극 개입한다.

1. 대본의 감정, 정보 밀도, 시청자, 플랫폼을 분석한다.
2. 최근 영상의 포맷·주조색·배경·자막 효과를 확인한다.
3. 서로 비슷하지 않은 콘셉트 3개를 제안하고 하나를 추천한다.
4. 선택된 콘셉트를 배경, 이미지, 아이콘, 도형, 타이포, 자막, 전환, 질감과 조명에 일관되게 적용한다.
5. 결과가 평범하거나 최근 영상과 닮았으면 다른 미술 방향으로 다시 제안한다.

### 캐주얼 디자인 도구상자

AI는 사용자가 하나씩 요청할 때까지 기다리지 말고 **비주얼 디렉터로 적극 개입해** 주제에 맞는 표현
매체와 장치를 먼저 골라 제안한다. 예능형만 반복 추천하지 않으며, 매번 아래 범주를 폭넓게 검토한다.

- **그림 방식**: 웹툰 패널, 손그림 드로잉, 화이트보드 드로잉, 낙서 애니메이션, 크레용·수채화·마커 질감
- **붙이기 방식**: 사진 오려 붙이기, 잡지 콜라주, 찢은 종이, 스티커, 테이프, 스크랩북, 페이퍼컷
- **오브젝트 방식**: 3D 미니어처, 클레이, 스톱모션 느낌, 생활 소품, 아이콘과 도형의 캐릭터화
- **사진·영상 방식**: 실사 전체 배경, 인물 컷아웃, 분할 화면, POV, 화면 속 화면, 전후 비교
- **타이포 방식**: 키네틱 타이포, 손글씨, 글자가 오브젝트처럼 움직이는 구성, 단어별 리듬 강조
- **리액션**: 표정 확대, 정지 화면, 순간 줌, 예상 밖의 컷어웨이, 전후 대비
- **코믹 문법**: 말풍선, 생각풍선, 속도선, 낙서, 스탬프, 의성어, 밈 타이밍
- **자막 연출**: 키워드 팝, 바운스, 노래방식 강조, 크기 반전, TV 예능형 보조 자막
- **모션**: 스냅 줌, 펀치인, 휩 전환, 오버슈트, squash-and-stretch, 빠른 분할 화면
- **구성**: 3단 반전, 설정→오해→펀치라인, 문제→과장된 반응→간단한 해결, 반복 후 변주

콘셉트 3개는 색만 다른 같은 레이아웃이 아니라 **표현 매체부터 달라야 한다**. 예를 들어 웹툰형,
사진 콜라주형, 손그림 애니메이션형처럼 제작 방식이 구별되는 후보를 낸다. 최근 작업에서 예능 자막을
썼다면 다음 작업에는 콜라주·드로잉·미니어처·키네틱 타이포 등을 우선 검토한다.

한 영상에는 가장 효과적인 디자인·연출 장치 2~4개만 선택한다. 모든 효과를 한 화면에 쌓지 않고 하나의
시각 언어와 보조 스타일 한 가지 안에서 반복·변주한다. 가독성, 플랫폼 안전영역, 의미 단위 줄바꿈,
얼굴·제품·아이콘과의 비겹침은 재미 연출보다 우선한다.

주제별 기본 제안 예시는 다음과 같다.

- 설명형: 생활 속 시각적 비유 + 전후 비교 + 키워드 팝
- 제품형: 불편을 과장한 오프닝 + 제품 리빌 + 짧은 리액션
- 개그형: 설정→예상→반전 + 정지 화면 + 예능 보조 자막
- 후기·스토리형: 친근한 인물 중심 전체 배경 + 말풍선 + 감정에 맞춘 펀치인
- 건강정보형: 웹툰·손그림·콜라주·캐릭터·상황극 등에서 주제에 맞게 선택하되 핵심 정보·조건·주의사항을 정확히 전달
- 금융·수익형: 친근한 상황극과 시각적 비유를 쓰되 수익 가능성·수치·위험 조건을 과장하거나 누락하지 않기

콘셉트 제안 형식:

```text
A. 스타일명 — 전체 배경과 화면 분위기 / 팔레트 / 자막·아이콘 방식 / 추천 이유
B. 스타일명 — 전체 배경과 화면 분위기 / 팔레트 / 자막·아이콘 방식 / 추천 이유
C. 스타일명 — 전체 배경과 화면 분위기 / 팔레트 / 자막·아이콘 방식 / 추천 이유
추천: B — 이 주제의 핵심 감정을 가장 빠르게 전달하기 때문
```

사용자가 “알아서”를 선택하면 가장 적합하면서 최근 5개 영상과 덜 겹치는 콘셉트를 AI가 선택하고
선택 이유를 짧게 알린 뒤 진행한다.

### 이미지 생성 기능 활용

GPT/Codex에서 이미지 생성 도구를 사용할 수 있으면 선택된 스타일에 필요한 이미지를 직접 생성한다.
이미지 생성 전에 씬의 텍스트·자막·아이콘 슬롯을 먼저 확정하고, 각 프롬프트에 다음을 포함한다.

- 플랫폼과 `9:16` 세로 구도
- 피사체 위치와 시선 방향
- 자막·제목·아이콘이 들어갈 저정보 영역의 정확한 위치
- 영상 전체에서 공통으로 유지할 팔레트·조명·질감
- 필요한 경우 동일 인물·제품·장소 참조
- 허용할 이미지 내 텍스트와 금지할 깨진 문자·워터마크·무단 로고

이미지를 생성한 뒤 실제 결과를 눈으로 확인한다. 피사체가 자막 슬롯을 침범하거나 이미지 속 글자가
깨졌거나 스타일이 다른 씬과 어긋나면 프롬프트를 수정해 다시 생성한다. 한 프롬프트로 모든 씬을
기계적으로 반복하지 말고 공통 스타일은 유지하면서 샷 크기, 구도, 카메라 각도와 배경 밀도를 바꾼다.

Claude Code 등 현재 환경에서 이미지 생성 도구를 사용할 수 없으면 생성한 척하지 않는다.
대신 동일한 형식의 완성도 높은 씬별 이미지 프롬프트와 필요한 참조 에셋 목록을 작성하고,
사용자가 이미지를 제공하면 크롭·배치·scrim·모션을 적용한다. 외부 이미지를 임의로 다운로드하지 않는다.

### 스타일 후보군

아래 목록은 고정 템플릿이 아니라 아이디어 출발점이다. 주제에 맞춰 혼합하거나 새 스타일을 만들 수 있다.

- 시네마틱 실사: 영화 같은 전체 배경, 얕은 심도, 절제된 타이포
- 에디토리얼 콜라주: 잡지 레이아웃, 오려 붙인 이미지, 과감한 제목
- 페이퍼컷: 종이 질감, 수공예 레이어, 부드러운 그림자
- 레트로 프린트: 망점, 제한된 색, 인쇄물 질감과 굵은 활자
- 다크 랩: 어두운 전체 배경, 미시 세계, 차가운 발광 도해
- 클린 클리닉: 밝은 여백, 얇은 라인, 신뢰감 있는 정보 그래픽
- 볼드 그래픽: 큰 색면, 기하 도형, 고대비 아이콘과 빠른 전환
- 키네틱 타이포: 이미지보다 움직이는 글자와 리듬을 중심으로 구성
- 3D 미니어처: 작은 디오라마, 장난감 같은 오브젝트, 부드러운 조명
- 웹툰·코믹: 패널, 속도선, 말풍선, 리액션 컷
- 손그림 드로잉: 선이 실시간으로 그려지고 채색되는 과정, 낙서 화살표와 손글씨 메모
- 포토 스크랩북: 인물·사물 사진을 오려 붙이고 테이프·스티커·종이 조각으로 구성
- 클레이·스톱모션: 손으로 만든 듯한 캐릭터와 소품, 프레임 단위의 통통 튀는 움직임
- 데이터 다큐: 실제 자료 느낌, 차트, 지도, 타임라인, 절제된 모션
- 네온 디지털: 글로우, 유리 패널, 스캔 라인, 미래적인 UI
- 웜 라이프스타일: 자연광, 생활 공간, 따뜻한 색온도, 친근한 인물
- TV 예능: 강한 리액션 컷, 집중선, 스탬프와 다이내믹 자막

같은 영상 안에서 모든 스타일을 섞지 않는다. 하나를 주 스타일로 정하고 보조 스타일은 한 가지만
제한적으로 사용한다. “다양성”은 한 화면을 복잡하게 만드는 것이 아니라 영상마다 새로운 미술 방향을
선택하는 의미다.

## 14. 심의 게이트

건강·금융·수익 관련 영상은 `docs/COMPLIANCE.md`를 먼저 읽는다. 검사 대상은 대본뿐 아니라 **최종 화면 자막과 강조 문구 전체**다.

- 질병 치료·예방·진단 암시 금지
- 수익 보장, 무조건 성공, 절대적 표현 금지
- 개인 체험을 일반적인 효과나 수익처럼 단정하지 않기
- 출처 없는 통계·최상급·불안 자극 금지
- 제품·서비스의 실제 조건과 보상 구조를 확인하도록 안내

문제가 의심되면 임의로 의미를 바꾸지 말고 씬과 문장을 지목해 사용자에게 알린다.

## 15. 구현과 검증

- 애니메이션은 `useCurrentFrame()`, `interpolate()`, `spring()` 등 Remotion 프레임 기반 API로 만든다.
- CSS transition, CSS animation, 런타임 랜덤값에 의존하지 않는다.
- `videos/index.ts`에 새 영상을 등록한다.
- 타입 검사 후 `npm run studio`로 확인하고 `npm run make <slug> out/<고유한-이름>.mp4`로 렌더한다.
- 기존 `out/` 파일을 덮어쓰지 않는다.

렌더 전후에 다음 프레임을 검사한다.

1. 각 씬의 시작·중간·마지막
2. 자막이 가장 긴 프레임
3. 아이콘과 모션이 가장 크게 나타나는 프레임
4. 설명 자막과 리액션 자막이 동시에 등장하는 프레임
5. 첫 프레임과 마지막 CTA 프레임

다음 문제가 있으면 자동으로 위치·크기·줄바꿈·타이밍을 조정하고 다시 렌더한다.

- 자막·제목·얼굴·제품·아이콘·이미지 텍스트 간 겹침
- 플랫폼 UI 위험 영역 침범
- 어색한 한글 줄바꿈 또는 3줄 초과
- 글자·도형의 화면 밖 잘림
- 음성이 끝나기 전 씬 전환
- 자막이 음성보다 늦게 등장하거나 너무 빨리 사라짐
- 배경과 자막의 명암 부족
